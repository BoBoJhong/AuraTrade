## 4. 風險分析 (Risk Assessment)

### 🔴 Critical 風險 (立即處理)

#### Risk #1: AuthService 認證邏輯
```yaml
檔案: backend/apps/services/auth_service.py
函數: register_user(), login_user()
風險等級: Critical
覆蓋率: 0%

風險因素:
  - 安全性核心 (密碼處理、Token生成)
  - 多重驗證邏輯 (Email、密碼強度)
  - 錯誤處理分支 (已註冊、驗證失敗)
  - 無邊界條件測試 (空值、特殊字元)

影響範圍:
  - 用戶無法註冊/登入 → 系統完全不可用
  - 密碼洩漏 → 重大安全漏洞
  - Token偽造 → 未授權存取

建議測試案例 (12個):
  正常案例:
    - TC-UT-AUTH-001: 成功註冊新用戶
    - TC-UT-AUTH-002: 成功登入已存在用戶
  
  邊界條件:
    - TC-UT-AUTH-003: Email格式錯誤 (無@符號)
    - TC-UT-AUTH-004: 密碼過短 (< 8字元)
    - TC-UT-AUTH-005: 密碼無大寫字母
    - TC-UT-AUTH-006: 密碼無數字
    - TC-UT-AUTH-007: Email已被註冊
    - TC-UT-AUTH-008: 登入密碼錯誤
    - TC-UT-AUTH-009: 登入帳號不存在
    - TC-UT-AUTH-010: 帳號已停用
    - TC-UT-AUTH-011: 空值參數 (null/undefined)
    - TC-UT-AUTH-012: SQL Injection 防禦測試

優先級: P0 (本次測試週期必完成)
```

#### Risk #2: Security 密碼與Token處理
```yaml
檔案: backend/apps/core/security.py
函數: hash_password(), verify_password(), create_access_token()
風險等級: Critical
覆蓋率: 0%

風險因素:
  - 密碼雜湊演算法 (bcrypt 72-byte限制)
  - JWT Token 簽名與過期驗證
  - 無加密強度測試
  - 無Token偽造測試

影響範圍:
  - 密碼外洩 → 用戶資料全面曝露
  - Token偽造 → 系統權限繞過
  - 雜湊碰撞 → 認證機制失效

建議測試案例 (10個):
  密碼處理:
    - TC-UT-SEC-001: 正確雜湊密碼
    - TC-UT-SEC-002: 驗證正確密碼
    - TC-UT-SEC-003: 拒絕錯誤密碼
    - TC-UT-SEC-004: 處理超長密碼 (> 72 bytes)
    - TC-UT-SEC-005: 處理特殊字元密碼
  
  Token處理:
    - TC-UT-SEC-006: 生成有效Token
    - TC-UT-SEC-007: 驗證有效Token
    - TC-UT-SEC-008: 拒絕過期Token
    - TC-UT-SEC-009: 拒絕偽造Token
    - TC-UT-SEC-010: 拒絕格式錯誤Token

優先級: P0 (本次測試週期必完成)
```
